Top 7 — Ranked

1🥇 Durable Learning Rail — phase, node, plan jadi state server

Persist `phase`, status plan approval, dan node DAG aktif ke SQLite peserta. Saat restore, tampilkan rail ringkas: "Kamu di: Praktik node 2 dari 4 — Rule of thirds", plus "due review 1 konsep" dalam satu pandangan. Reload/reconnect/koneksi lemah tidak lagi menghapus posisi belajar.

Kenapa #1: Fondasi untuk hampir semua ide lain (transfer check, review queue, facilitator loop butuh durable state). Evidence menunjukkan phase sudah dikirim server tapi dibuang frontend; approval hilang saat reload. Value tertinggi, dependency terendah.
hooks: server.ts runTurn (phase sudah ada), participants table + kolom baru, /api/restore

2🥈 Real Spaced Retrieval Queue

Ganti "mastery < 0.5 → muncul banner" dengan queue persisted: due timestamp, interval, status selesai/undo per konsep. Masuk app → tawarkan tepat 1 soal retrieval. Benar → interval memanjang; salah/"tidak tahu" → repair micro-loop + interval pendek. Tanpa notifikasi, tanpa utang review — "nanti aja" selalu sah.

Kenapa #2: Retention adalah janji utama tutor (lupakan = hilang), dan evidence menunjukkan attempts sudah punya timestamp tapi tidak ada state waktu sama sekali. Ini fitur paling langsung terasa oleh peserta setelah workshop selesai.
hooks: quiz_attempts (created_at sudah ada), /api/mastery, due-review card UI

3🥉 Try→Hint→Explain Help Ladder (Mode "Coba Dulu")

Kartu bantuan eksplisit 3 tingkat: "cek langkah gue" → "petunjuk kecil" → "contoh serupa". Pilihan dikirim sebagai turn context; fading HIGH/MED/LOW yang sekarang tersembunyi di prompt jadi terlihat dan dikendalikan peserta. Tiap jalur bantu berakhir di quiz check yang sama.

Kenapa #3: Tren pasar 2025-26 konvergen ke sini (Study Mode, Guided Learning). Evidence menunjukkan fading sudah ada di prompt — ini cuma membuatnya visible + learner-controlled. Buat minta bantuan jadi skill, bukan kegagalan.
hooks: envelope ask (baru), AGENTS.md fading rules, QuizBlock flow

4Misconception Fingerprint + Dominant Wrong Answer

Persist bukan cuma benar/salah tapi opsi salah yang dipilih — jadi "fingerprint" miskonsepsi per konsep. Facilitator lihat cluster: "12 peserta mengira mencuci = buat manis", bukan sel merah generik. Learner dapat retrieval yang menyasar kebingungan spesifiknya sendiri.

Kenapa: Data sudah tersimpan (selected_label di quiz_attempts) tapi tak dipakai. Dua pihak untung sekaligus dari evidence yang sama: miskonsepsi jadi spesifik, bukan angka. Input langsung untuk review-queue (#2).
hooks: quiz_attempts.selected_label (sudah ada), /api/host-matrix, repair micro-loop

5Repair → Retry Micro-loop

Setelah salah/"tidak tahu": kartu repair ringkas (satu distingsi kunci + satu micro-step) lalu langsung 1 soal analogi baru sebelum lanjut. dont_know dibedakan dari salah tebak — uncertainty diganjar lebih ringan daripada miskonsepsi yakin.

Kenapa: Spec referensi mewajibkan "repair the node before building on it" — sekarang belum ada. Menutup gap sebelum tutor membangun di atas fondasi rapuh. Murah: reuse dont_know flag + mastery untuk pilih scaffold level.
hooks: QuizBlock feedback state, AGENTS.md repair rule, mastery-based fading

6One-page Post-workshop Outcome Report

Report client-ready otomatis setelah workshop: kehadiran, konsep yang dicoba, mastery kohort, tingkat "tidak tahu", 3 gap terbesar — tanpa transcript, tanpa ranking individu. Plus rekomendasi tema sesi lanjutan berbasis evidence.

Kenapa: Ini mesin bisnis: "kami bikin workshop" jadi "ini bukti dampaknya" — alasan renewal/upsell. Paling murah dari semua fitur facilitator (data sudah ada, cuma perlu render + export).
hooks: /api/host-matrix, quiz_attempts, host token boundary

7Confidence Tap — "Yakin / Lumayan / Belum yakin"

Setelah quiz feedback, satu tap kalibrasi diri. Dipasangkan privat dengan hasil: "yakin tapi salah" → koreksi kontras + prioritas review; "ragu tapi benar" → bukti bisa dipercaya, ulang nanti. Tanpa analitik palsu, tanpa paparan publik.

Kenapa: Metakognisi = belajar mengenali sendiri apa yang rapuh. Kolom kecil di SQLite, satu tap di UI — murah. Tapi menambah dimensi yang mastery score sendiri tak punya: keyakinan vs bukti.
hooks: QuizBlock feedback, quiz_attempts + kolom confidence, review queue

Yang ditolak (dengan alasan)

• Streak counter / badges / leaderboard — melanggar anti-slop identity; risk jadi cheap gamification tinggi. Replaced by: Janji 2 Menit (return cue yang jujur).
• Voice rehearsal / avatar roleplay — dependency besar (voice SDK), value belum terbukti di konteks corporate ID. Teks dulu.
• Live "pause and reteach" alerts — butuh durable identity + polling; terlalu besar untuk sekarang, dan belum ada bukti fasilitator mau ngintip dashboard di tengah sesi.
• Session library / akumulasi lintas workshop — kontra produktif dari contrarian frame: akumulasi menimbulkan risiko surveilans & stale label; bounded session + opt-in carry-forward lebih selaras dengan privacy expectation peserta korporat.
• KaTeX/math rendering — sudah di-defer di tiket #005; tetap deferred sampai ada materi math.

Contrarian notes (dianggap, tidak di-adopsi penuh)

Frame contrarian menghasilkan 7 pandangan alternatif yang layak diingat: (1) tutor kadang menolak menjawab sebelum learner mencoba — sebagian sudah ada via fading, bisa diperkuat nanti; (2) hilangkan mastery % dari vocab learner — diganti action choice; (3) chat bukan satu-satunya interface; (4) standardisasi struggle dulu sebelum personalisasi; (5) field-test obligation vs spaced repetition; (6) reset sebagai privacy feature; (7) dashboard menunjukkan kegagalan sistem, bukan learner. Ide #7 (dashboard = sistem gagal) patut diingat saat desain heatmap: dominan salah = mungkin soalnya ambigu, bukan muridnya bodoh.
